# 孫子兵法 — TECHNICAL ARCHITECTURE & PERFORMANCE SPECIFICATION

**v1.0 · subordinate to `manifesto.md`. Where they disagree, the manifesto wins.**
Next.js 15 App Router · React 19 · TS strict · Tailwind v4 · three r170+ · @react-three/fiber v9 · drei · @react-three/postprocessing · GSAP 3 + ScrollTrigger · zustand.

Three doctrine clauses do more architectural work here than any performance target:

1. **D is monotonic.** The ink field is durable state that must survive a chapter unmount. It cannot live in a chapter's scene graph.
2. **Two clocks.** `tCamera` is bidirectional and scroll-bound; `tInk` is a high-water mark. One signal, two integrators, neither in React state.
3. **Cuts fire on reader action, never on scroll.** Every hard cut is therefore the most designed moment in the site — exactly where a compile stall or texture upload will land unless we forbid it structurally.

---

## 1. RENDERING TOPOLOGY

**One `<Canvas>`, one `WebGLRenderer`, for the entire site.**

Canvas-per-chapter fails on four counts. Browsers cap live contexts (Chrome 16, WebKit lower and adaptive) and evict the *oldest* silently — a reader at Chapter 9 finds Chapter 3 black on scroll-back, with no catchable error. Contexts share nothing: a texture or compiled program uploaded to A is unusable from B, so thirteen contexts means thirteen uploads of the paper, fibre and sizing maps and thirteen compiles of the ink program. Match-cutting between two canvases puts the cut at the mercy of the browser compositor rather than our own frame. And the ink field — the one thing that must persist across the whole read — cannot be shared between contexts at all, which alone settles it.

```tsx
<Canvas gl={{ antialias:false, alpha:false, powerPreference:'high-performance',
              preserveDrawingBuffer:false }}
        dpr={profile.dpr} frameloop="always" flat>
  <InkField />               {/* singleton: ping-pong FBOs, owns D/M/S/A. Never unmounts. */}
  <CameraRig track={track}/> {/* one PerspectiveCamera + one OrthographicCamera */}
  <Suspense fallback={null}>
    <ActiveChapter key={chapter} />   {/* the ONLY thing that unmounts */}
  </Suspense>
  <Composer profile={profile}/>
</Canvas>
```

The registry maps chapter id → `{ track, load: () => import(...), preload: string[] }`. Antialias is off: MSAA on a half-float target is expensive and we composite grain at device resolution anyway; edges come from `fwidth`-based analytic AA in the ink and glyph shaders.

**Camera rig.** Story is the perspective camera, Codex the orthographic one; the switch is a `state.camera` reassignment with a matched frustum, not an fov lerp, which cannot reach orthographic. Focal length uses `setFocalLength()` against a fixed 35mm sensor so 24/40/85/180 are literal, greppable values. Scenes never own a camera — they publish an arc-length-parameterised `CameraTrack` and the rig samples it.

**What it costs.** Disposal becomes our problem (§9). A scene that throws takes the site down, so the chapter subtree needs an error boundary falling back to that beat's poster. Scenes must agree on world scale and the shared fog term. There is one program cache — a benefit, if chapters actually share GLSL chunks (§11).

## 2. SCROLL ARCHITECTURE

Document height is generated by DOM: one viewport-height per beat, canvas `position: fixed` behind an `<article>` of `<section>`s. The 3D never sets scroll height and never scrolls the document.

**The bug this section exists to prevent:**

```tsx
// WRONG. This is the 20fps.
ScrollTrigger.create({ onUpdate: (self) => setProgress(self.progress) })
```

`setProgress` runs on a component above `<Canvas>`. Every scroll frame re-renders that tree; R3F reconciles; new prop objects hit materials; three.js flags uniforms dirty; allocation churns the nursery — the 16.6 ms budget is gone before a draw call. React 19 adds a subtler failure: the concurrent scheduler may defer that update by a frame, so DOM typography and the WebGL camera desynchronise, which reads on screen as the letterbox sliding independently of the shot. No amount of `memo` fixes it. Keep continuous values out of React entirely.

**Two tiers.** Continuous scroll is a mutable module singleton written once per rAF. Discrete scroll is a `useSyncExternalStore` subscription that notifies only when a *quantised* field changes.

```ts
// src/lib/scroll.ts — written once per rAF, read directly in useFrame.
export const scroll = { raw:0, progress:0, smooth:0, velocity:0, direction:1 as 1|-1,
                        chapterIndex:-1, chapterProgress:0, chapterSmooth:0,
                        atRest:true, locked:false };
export const ink = { high:0, beatHigh:new Float32Array(BEATS) };  // the second clock

function tick(dt: number) {
  scroll.progress = clamp01(window.scrollY / (docH - vh));
  const k = 1 - Math.exp(-dt * 9.0);              // frame-rate independent; never `+= (b-a)*0.1`
  scroll.smooth += (scroll.progress - scroll.smooth) * k;
  ink.high = Math.max(ink.high, scroll.progress); // tInk never decreases
  publishDiscrete();                              // only if quantised fields moved
}
```

```tsx
useFrame((state, dt) => {
  track.sample(scroll.chapterSmooth, rig.current);  // tCamera: bidirectional
  mat.uniforms.uInk.value = ink.beatHigh[beat];     // tInk: high-water mark
});
```

`publishDiscrete` compares `{chapterIndex, beatIndex, direction, atRest, locked}` and allocates a new object only when one differs — `useSyncExternalStore` requires a **cached** snapshot reference or React loops infinitely. A few renders per minute, not per frame.

**Where GSAP fits.** ScrollTrigger owns DOM work only: pinning, the bamboo-slip HUD, typography reveals, the letterbox aspect tween. It does not feed the 3D signal, because a passive scroll listener plus rAF is trivially idempotent — which sidesteps the StrictMode trap (§12.2) and keeps ScrollTrigger off the render loop's critical path. Where GSAP must drive a WebGL value it tweens a plain object that `useFrame` reads: `gsap.to(aperture, { value: 2.76, duration: 0.7 })`. The scroll handler writes `scrollY` and nothing else; section geometry is cached and recomputed on a debounced `ResizeObserver`.

## 3. SSR AND HYDRATION

The page is server-rendered and *meaningful without WebGL*. The `<article>` — thirteen chapters, Chinese, translation, Historian apparatus, decision nodes as real `<fieldset>`s — is the document, the SEO surface and the accessibility spine (§10). The canvas is decoration over it.

```tsx
const Stage = dynamic(() => import('@/three/Stage'), { ssr: false, loading: () => null });
```

That boundary wraps **only** the canvas subtree, and nothing under `src/three/**` may be imported by a server component, even for a type — use `import type`. The crash is not React's: it is three addons and `postprocessing` touching `document.createElement('canvas')` at module evaluation, which throws before any component renders.

Everything device-dependent — quality tier, `prefers-reduced-motion`, audio consent, persisted decisions — is client-only and must not affect first render. zustand's `persist` rehydrates after mount; `useSyncExternalStore` gets a stable `getServerSnapshot`; the letterbox element, whose aspect is a state variable, carries `suppressHydrationWarning`.

**First paint is the poster frame:** a letterboxed 2.39:1 AVIF at 1600px (~170 KB) over an inline LQIP, with the 篆書 title as inline SVG paths — never a webfont, because no glyph may fade or swap in. This is the LCP element, in the server HTML. The handover to WebGL is a **match cut on ink**, not a fade: the poster is authored as the literal first frame of the scene, removed in the same rAF the renderer reports its first presented frame. Done right the reader cannot name the moment it went live.

## 4. ASSET PIPELINE

This project is not mesh-heavy. *Armies are strokes, not meshes with ink textures plastered on* — the polygon budget is small; the weight is render targets, atlases and audio.

**Geometry.** glTF + **meshopt** by default: a ~30 KB decoder against Draco's ~200 KB wasm, 3–5× faster decode, quantised attributes reaching the GPU without a float expansion. Draco only where an asset exceeds 500 KB post-meshopt and prefetch amortises the decode. Terrain ships as a displaced plane plus a **KTX2 R16 heightmap**, not a mesh — an order of magnitude smaller, and it gives the Ch. 10 contour shader analytic height for free.

**Textures.** KTX2/Basis always. ETC1S (~0.5 B/px) for parchment, fibre and albedo where block artefacts hide in noise; **UASTC** (~1 B/px) for anything the ink physics samples — sizing maps, brush coverage, SDF atlases — because ETC1S ringing in the 0.02 < D < 0.28 band is exactly where the art direction lives. Both stay compressed in VRAM, which is the point: an uncompressed RGBA8 2048² is 21 MB with mips, and four of those is an iOS context loss. Channel-pack: the brush atlas is one 2048² UASTC sheet of 64 strokes at 256², **R = coverage, G = 飛白 fibre mask, B = distance-to-edge** for the rim term. Three maps, one fetch, one upload.

**No EXR/HDR environment, anywhere.** There is no PBR here; the ground is paper and the subject is ink, so an HDRI buys specular response we have banned. Lighting is a three-band analytic term plus baked vertex AO. One exception: Chapter 12's fire irradiance, shipped as **9 spherical-harmonic coefficients in a uniform**, animated by burn intensity. Zero bytes on the wire.

**Byte budgets** (brotli, over the wire). Hard rules: no chapter over 4.0 MB, no texture over 4 MB, complete read ≤ 34 MB.

## 5. SHADER INVENTORY

Costs at 1920×1080 on an M1 (8-core GPU), per frame. High-tier total **≈ 4.4 ms**, leaving ~12 ms for scene, post and browser.

| # | Program | Key uniforms | Technique | Cost |
|---|---|---|---|---|
| 1 | **Ink field sim** (GPGPU, not a material) | `uPrev, uSizing, uFibre, uWind, uK, uDt, uDeposits[8]` | Two RGBA16F ping-pong targets packing **R=D, G=M, B=tide/age, A=S**. Advect M by wind → `bleed = f(M)·(1−S)·aniso(G)` as a 9-tap kernel weighted **5–8× along fibre θ vs across** (K∥ 0.10–0.16, K⊥ 0.018–0.032 UV/s) → `D = max(D_prev, D_bleed)` → tide line where `∂M/∂t` crosses zero → M decays on the 4–12 s curve | 1.4 ms @ 2048² |
| 2 | **Ink dispersion + dark rim** | `uInk, uFront, uRimWidth, uRimGain, uScale, uTime` | Curl-advected mask, smoothstep front displaced by 4-octave FBM, plus the accumulated rim (below) | 0.6 ms |
| 3 | **Wet-paper diffusion** | `uM, uTheta, uR` | Separable soak along θ and θ+90° with asymmetric radii; folded into #1 as a 5-tap on medium/low | 0.3 ms |
| 4 | **Brush edge alpha + SDF glyph** | `uAtlas, uPressure, uVelocity, uPx` | MSDF, `fwidth` analytic AA, pressure-modulated width; 飛白 as **amplitude dropout** against the atlas G channel gated by velocity — the reserve ran out, the tone did not change | 0.2 ms |
| 5 | **Water-surface distortion** | `uNormal, uFlow, uAmp` | Dual-scrolling normal derivative from a 512² RG map, refraction offset in paper-space UV. No reflection, no Fresnel tint (no blue) | 0.4 ms |
| 6 | **Ember / spark, additive** (Ch. 12) | `uPos, uLife, uRamp` | Point sprites, `pow(1-r,3.0)` falloff on a vermilion ramp, writing `uBloomMask` to MRT so the composer blooms these and nothing else | 0.5 ms @ 65k |
| 7 | **Height fog** — *god-rays cut* | `uDepth, uM, uH0` | `fog = 1 - exp(-h(z)·(0.22 + 0.9·M))`, M read from the ink field, so fog of war and moisture are one variable. 12-tap / 6-tap / analytic | 0.7 / 0.35 / 0.05 |
| 8 | **Paper grain + vignette** — *flare cut* | `uGrain, uDpr, uVig` | Static FBM in **paper space**, locked to device pixels: paper tooth, not film grain. Animated grain crawls and is a LUT-era tell | 0.25 ms, 1 blit |
| 9 | **Topographic contour** (Ch. 10) | `uHeight, uInterval, uIndexEvery` | Analytic isolines, derivative-normalised (below). No line meshes, no zoom popping | 0.3 ms |

**The rim is what makes #2 read as ink rather than as a dissolve.** A curl-advected mask crossed with a smoothstep front gives a *fade*. Real ink is darkest **at the edge**: evaporation is fastest at the pinned contact line, so carbon is carried outward and deposited there (邊緣效應, the coffee-ring effect). The rim is the signature of drying and must intensify as M falls.

```glsl
float front = uFront + fbm4(uv * uScale + curl(uv, uTime)) * 0.06; // 4-octave displacement
float d     = texture(uInk, uv).r;
float edge  = smoothstep(front - w, front + w, d);
float rim   = exp(-pow((d - front) / uRimWidth, 2.0)) * uRimGain * (1.0 - M);
float D     = clamp(edge * uCore + rim, 0.0, 1.0);   // rim ADDS density, never alpha
```

Two rules keep it honest: the FBM displacement applies only in the 0.02 < D < 0.28 band (isotropic Gaussian anywhere is printer ink, and banned), and the rim contributes to **D**, not opacity — a rim that fades is a bug in the Ink Law.

```glsl
// #9: lines hold ~1px at any camera distance; every 5th is an index contour.
float f = h / uInterval;
float line = 1.0 - smoothstep(0.0, 1.5, abs(fract(f - 0.5) - 0.5) / fwidth(f));
```

**Glyphs stamp into the ink field** through #1's `uDeposits` rather than compositing over it — that is what makes "if it cannot get wet, it is not a glyph in this world" true in code. **God-rays and anamorphic flare are doctrine deletions**, so #7 is fog only and the sole streak in the build is vermilion at 0.4× bloom via #6's mask. Cutting the ray-march saved more frame time than any other single decision; the doctrine got there first.

## 6. PARTICLE STRATEGY

- **< 2,000 — `InstancedMesh`, CPU-updated.** Real geometry, per-instance matrix and colour. Arrows, bamboo slips, banner cards, seal marks. Below ~2k the matrix write is under 0.3 ms and the flexibility is worth it.
- **2,000–50,000 — one `Points` or instanced quad, all motion in the vertex shader.** Position is a pure function of `(hash(id), uTime)`: no attribute uploads after the first, no CPU work, one draw call. Mist motes (9–11), rain (9), march dust, Ch. 5 rout residue. If a system needs no history, it needs no simulation.
- **> 50,000, or motion requiring feedback** (history, collision, curl advection with respawn) **— GPGPU FBO.** Position and velocity in two RGBA16F targets, two draws per step, rendered as a `Points` cloud indexed into the position texture.

**Exactly one system crosses into GPGPU: Chapter 12 fire**, at 256² = 65,536 embers high (128² medium, 4,096 sprites low). Nothing else earns it — notably the rout does *not*, because a rout is bloom plus wind in the ink field until D < 0.05, not a particle system. The Ink Law's ban on floating ink and particle smoke deletes the two systems that would otherwise have been the most expensive here. GPGPU infrastructure is shared with the ink field: one `FBOSim` class serves both.

## 7. POST-PROCESSING STACK

1. **Scene → HDR half-float RT** (MRT: colour + bloom mask).
2. **DOF** — first: it needs untouched depth and must precede anything that decorrelates colour from depth.
3. **Bloom** — masked by the MRT channel so vermilion blooms at 0.4× and **gold never does**. A luminance-threshold bloom would bloom the gold; that is a doctrine violation implemented as a shader bug, so the mask is mandatory, not an optimisation.
4. **Ink composite** — the ink field composited in *paper space*, **after** DOF. Ink is on the substrate, not in the world; blurring a bleed edge by camera depth puts the paper inside the scene and destroys the metaphor.
5. **Tone map** — AgX with a custom base. **ACES is banned:** its highlight desaturation path skews hue toward blue at the top of the range, and "no blue, ever" is a colour ruling. Reinhard is an acceptable low-tier substitute on a near-monochrome image.
6. **Grain + vignette + letterbox mask — one merged pass, after tone mapping, at 1:1 device pixels.** Grain before tone mapping gets crushed and crawls.

The **letterbox itself is DOM**, not a shader: it is the mounting silk (裱), must be crisp at any DPR, is tweened by GSAP as a state variable, and must clip DOM typography as well as the canvas. The shader pass only masks the render to the safe area so we do not pay for unseen pixels — a 2.39:1 crop of a 16:9 buffer is **26% of fragment cost gone free**, and 2.76:1 at a decision node is 34%.

**Low tier:** drop DOF and bloom (vermilion gets a baked 3 px sprite halo), keep grain and vignette in one blit. **Grain is never disabled** — it is the substrate, not an effect.

## 8. PERFORMANCE BUDGET & ADAPTIVE QUALITY

**Capability detection, not UA sniffing.** The UA string says what a browser wants you to believe: a high-end iPad reports as a Mac, a cheap Android as Chrome on Linux. The signals that correlate are WebGL2 presence, `MAX_TEXTURE_SIZE`, `EXT_color_buffer_half_float` + `OES_texture_float_linear`, `deviceMemory`, `hardwareConcurrency`, and raw pixel count (`screen.w × screen.h × dpr²`). Score them, pick a **starting** tier, then release the probe context with `WEBGL_lose_context` — a leaked probe can cost the real canvas its context on iOS.

| | **High** | **Medium** | **Low** |
|---|---|---|---|
| DPR clamp | 2.0 | 1.5 | 1.0 |
| Ink FBO | 2048² RGBA16F | 1024² RGBA16F | 1024² RGBA8 packed |
| Ink tick rate | 60 Hz | 30 Hz | 20 Hz |
| Ch. 12 particles | 65,536 GPGPU | 16,384 GPGPU | 4,096 sprites |
| Particle scale (others) | 1.0 | 0.5 | 0.22 |
| Shadows | 1× 1024 PCF, contact only | none (baked AO) | none |
| Fog | 12-tap | 6-tap | analytic |
| Post | DOF + bloom + grain | bloom + grain | grain only |
| Anisotropy | 8 | 4 | 1 |

**Watchdog.** Rolling 90-frame window, EMA frame time, asymmetric hysteresis: **demote** when p90 > 20 ms for two consecutive seconds; **never auto-promote mid-chapter** — promotion causes a compile hitch and, worse, oscillation. Promotion is allowed once per chapter boundary, after p90 < 10 ms for 10 s. Suppress sampling for 1.5 s after a scene swap: compile and upload stalls poison the window and would demote a device that is fine.

| Device | Tier | Frame p90 / p99 | GPU-resident | TTI |
|---|---|---|---|---|
| M1 MacBook Air, 1440×900@2 | High | 11 / 14 ms | ≤ 420 MB | ≤ 2.5 s |
| Pixel 6a class, 1080×2400 @1.5 | Medium | 18 / 24 ms (45 fps floor) | ≤ 220 MB | ≤ 4.0 s |
| 2019 Intel MBP, Iris Plus 645 | Low | 28 / 33 ms (30 fps lock) | ≤ 160 MB | ≤ 5.0 s |

Dioramas step at 24 fps while camera and interface run at 60 — a doctrine clause that is also a 60%-off animation budget. Take it.

## 9. MEMORY & LIFECYCLE

Nothing in three.js is garbage collected. A chapter unmount must return `renderer.info.memory` to baseline, and we assert it in dev:

```ts
export function disposeScene(root: THREE.Object3D) {
  root.traverse((o) => {
    const m = o as THREE.Mesh;
    m.geometry?.dispose();
    for (const mat of ([] as THREE.Material[]).concat(m.material ?? [])) {
      for (const v of Object.values(mat)) (v as THREE.Texture)?.isTexture && v.dispose();
      mat.dispose();
    }
  });
}
// gate: mount/unmount a chapter twice; geometries and textures must return to ±0.
```

**The leak that will happen is render targets.** `WebGLRenderTarget` owns a texture, a depth renderbuffer and a framebuffer; nothing disposes it when the JS object is collected, and R3F does not auto-dispose targets made in `useMemo`. Thirteen chapters each allocating a 2048² RGBA16F ping-pong pair is 13 × 2 × 32 MB = **832 MB** — a hard context loss on iOS around chapter five. This is the strongest argument for the ink field being a resident singleton: the largest allocation in the project is created once and never freed, so it cannot leak.

Four more, in likelihood order. **Program cache growth** — cloning a material per instance, or letting R3F recreate one on a prop identity change, accumulates compiled programs; each is a few hundred KB of driver memory and a 5–60 ms compile stall. **drei's `useTexture`/`useLoader` cache is never evicted** — `texture.dispose()` frees the GPU copy while the cache still hands out the dead object, so the next chapter gets a black texture; pair disposal with `useLoader.clear(THREE.TextureLoader, url)`. **GSAP timelines holding three.js references** keep the whole scene graph alive; scope them in `gsap.context()` and `revert()` on cleanup. **Web Audio nodes** are not collected while connected; disconnect in `onended`.

## 10. ACCESSIBILITY & REDUCED MOTION

**`prefers-reduced-motion` is a render path, not a setting.** Per doctrine: do not run the soak; cut to the dried state of the same information. The ink sim runs N substeps into the FBO in one off-screen frame and presents the settled result; the camera cuts instead of tracking; the letterbox changes aspect instantly; particles are off; DOF and bloom are off (there is no motion to blur); grain stays. The site becomes a book of finished plates — every deposit, tide line and seal present and permanent, only the physics of arriving withheld. Nothing in the argument is lost, which is the test.

**Keyboard navigation is real navigation**, not simulated scrolling, because the DOM is the source of truth. Each beat is a `<section id tabindex="-1">`; `↓ / → / Space / J` advance via `scrollIntoView({ behavior: reduced ? 'auto' : 'smooth' })`; `Home`/`End` and the bamboo-slip chapter list (a `<nav><ol>`) give random access. The decision node must be operable without scrolling: a `<fieldset>` with two real `<button>`s, focus-trapped while `scroll.locked`, moving focus to the analysis region on commit. Focus cannot be lost across a scene swap, because the swap happens inside a canvas that is `aria-hidden`.

**Screen readers.** `<canvas role="presentation" aria-hidden="true">`; the content is the article — Chinese in `<p lang="zh-Hant">`, translation adjacent, apparatus in an `<aside>`. The non-obvious requirement is that **ink state must be narrated**, or the central metaphor is sighted-only: a polite `aria-live` region reports what the mark did and what it cost — *"Your stroke ran into the valley and stopped. The page is now 18 percent ink."*

**Captions.** The Historian is the only human voice: WebVTT on the audio element's `<track>`, on by default, set in the apparatus grotesque under the frame, never inside it. The Text is never spoken and needs no caption — it is already ink on screen and mirrored in DOM. A persistent, keyboard-reachable audio stop is required (beds exceed four seconds: WCAG 1.4.2). Honour `prefers-contrast: more` by widening the paper/ink delta, and `prefers-reduced-transparency` on the HUD.

## 11. LOADING CHOREOGRAPHY

Chapters are code-split behind `React.lazy` with **one Suspense boundary inside the Canvas**, wrapping only the chapter subtree, `fallback={null}` — never a spinner in the frame.

**Prefetch heuristic:** when `scroll.chapterProgress > 0.6`, direction is forward, and `|velocity|` is below the fling threshold (do not prefetch during a scrub), `import()` N+1 and fetch its textures at `fetchpriority="low"`. Backward travel prefetches N−1 only if it was evicted.

**The swap gate is not "module loaded."** It is `compiled && uploaded`:

```ts
await import(chapter.load);
buildOffscreen(scene);
await renderer.compileAsync(scene, camera);              // KHR_parallel_shader_compile
for (const t of scene.textures) renderer.initTexture(t); // force upload off the cut
allowSwap = true;
```

Skip this and a 200–400 ms stall lands exactly on a hard cut — the moment doctrine says the reader caused. Shared GLSL chunks matter here: chapters that `#include` the same ink and grain chunks hit the program cache and compile in single-digit milliseconds.

**What the reader looks at.** Never a spinner, never a percentage. The cover is the ink transition itself — a designed 900 ms wash whose *middle extends to roughly four seconds* without reading as a wait, because it is ink doing what ink does. If warm-up outruns that, the Historian's opening line for the incoming chapter is the buffer; he is a narrator, not a progress bar, and the reader never learns the difference. Cold start gets the largest budget of all: the audio spec already schedules 4.0 s of silence over the poster after unlock. That is the first scene's load window, and it is free.

## 12. RISK REGISTER

1. **iOS Safari WebGL memory ceiling.** WebKit discards the context around 256–384 MB of GPU-backed memory per tab, with no catchable error — only `webglcontextlost`. *Mitigation:* KTX2 everywhere, one context, one chapter resident, ink FBO capped at 1024², half-float not float, `preserveDrawingBuffer:false`, hard DPR clamp. Handle `webglcontextlost` with `preventDefault()`, show the current beat's poster, restore. Test on device; the simulator does not model this.
2. **ScrollTrigger under React 19 StrictMode.** Dev mounts effects twice, so `ScrollTrigger.create()` runs twice; with `pin: true` each instance injects its own pin-spacer, document height doubles, and every start/end is wrong. The symptom is "broken in dev, fine in prod," which people ignore until it isn't. *Mitigation:* `useGSAP` from `@gsap/react` with a scope and `revert()` cleanup; a stable `id` per trigger with `ScrollTrigger.getById(id)?.kill()` before create; `ScrollTrigger.config({ ignoreMobileResize: true })` for the iOS URL-bar resize storm; one debounced `refresh()` after fonts and images settle. Structurally: the 3D signal does not depend on ScrollTrigger at all.
3. **Compile stalls on the cut.** See §11. *Mitigation:* the `compileAsync` gate, a shared chunk library, and a CI check that fails if a chapter introduces more than two new programs.
4. **Monotonic D versus scroll-back.** The likeliest *design* bug: a reader scrubs back into a beat, the deposit replays, and tide lines accumulate fifty deep. `D = max()` hides it; the tide line does not. *Mitigation:* deposits are idempotent, keyed `(beat, strokeId)` in a committed set; re-entry replays the **field**, never the events.
5. **Float render target support.** Some Android drivers expose half-float targets without `OES_texture_float_linear`, so bilinear silently degrades to nearest, and the RGBA8 fallback bands precisely in the 0.02–0.28 range the art direction lives in. *Mitigation:* detect at probe time; on RGBA8, pack D across R+G as 16-bit fixed point with manual bilinear. Test this path; do not assume it.
6. **CJK font weight.** A full 楷書 face is 5–15 MB. *Mitigation:* display glyphs are SDF atlases, not fonts, so only body Chinese needs a webfont — subset per chapter by `unicode-range` from the actual canon, 40–90 KB woff2 each. Never `font-display: swap` on a face rendering the Text: no glyph may swap in.
7. **Audio unlock timing.** Scheduling the seal — the loudest, most important sample in the build — from a promise continuation misses Safari's gesture window and it silently does not play. *Mitigation:* `start(ctx.currentTime + 0.005)` synchronously inside the pointer handler, plus a test asserting `pointerup → start()` in the same task.
8. **Scroll hijacking.** The pressure to add Lenis for "silkiness" is constant. It breaks keyboard paging, `scrollIntoView`, find-in-page and iOS momentum, and adds a frame of latency. *Ruling:* no document-level hijack; damping happens on `tCamera` inside `useFrame`.
9. **Content pipeline outrunning the engine.** Thirteen chapters each need a track, scene, node, audio and text. *Mitigation:* build **Chapter 3 end-to-end first** — it carries the thesis and the hardest moment in the site — and freeze the `CameraTrack`, `SceneDefinition` and `DecisionNode` interfaces against it before any other chapter starts.
10. **The reduced-motion path rotting.** Built once, never looked at again, broken by chapter seven. *Mitigation:* Playwright screenshot pairs (motion / reduced) per beat in CI, and reduced-motion as the **default** in the test suite, so it is the path exercised most.
